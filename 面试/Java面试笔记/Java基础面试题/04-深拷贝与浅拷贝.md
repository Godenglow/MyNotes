# 深拷贝与浅拷贝

> [!question] 疑问
> 什么是浅拷贝？什么是深拷贝？区别是什么？

## 一图看懂

![[深拷贝与浅拷贝.svg]]

## 定义

**浅拷贝**：只复制对象本身和内部的**值类型字段**，不复制内部的**引用类型字段**。新对象和原对象的引用字段指向同一块内存，一方修改会影响到另一方。

**深拷贝**：无论值类型还是引用类型字段，全部递归复制一份。两个对象完全独立，互不影响。

```java
class Student implements Cloneable {
    String name;
    int age;
    Address address;          // 引用类型字段

    // 浅拷贝：address 仍指向同一个 Address 对象
    @Override
    protected Student clone() throws CloneNotSupportedException {
        return (Student) super.clone();
    }

    // 深拷贝：引用字段也复制一份
    @Override
    protected Student clone() throws CloneNotSupportedException {
        Student copy = (Student) super.clone();
        copy.address = address.clone();   // 引用字段再克隆一次
        return copy;
    }
}
```

> [!warning] 关键区分
> 判断深浅拷贝只看一点：**引用类型的字段有没有被重新复制**。值类型（`int`、`long` 等）在两种拷贝里都是直接复制值的。

## 面试高频追问点

1. **怎么实现深拷贝？**
   - 重写 `clone()`，对每个引用字段递归调用克隆（字段多时很繁琐）
   - 序列化方式：把对象写成字节流再读回来（类要实现 `Serializable`）
   - 手写拷贝构造器 / 工厂方法（推荐，最可控）
2. **`clone()` 的坑**
   - 类必须实现 `Cloneable` 接口（它是个空接口），否则调用 `clone()` 抛 `CloneNotSupportedException`
   - `Object.clone()` 是 `native` 方法、`protected` 修饰
   - 《Effective Java》的观点：**尽量少用 `clone()`**，优先用拷贝构造器或工厂方法
3. **String 字段为什么浅拷贝也"安全"？**
   `String` 不可变，共享引用不会被改出问题——所以面试手写深拷贝时，`String` 和基本类型字段不用管，重点处理可变的引用字段（数组、集合、自定义对象）。
4. **`Arrays.copyOf()` / `ArrayList` 的 `clone()` 是深还是浅？**
   都是**浅拷贝**：只复制了数组/列表这一层，里面的元素引用还是共享的。
