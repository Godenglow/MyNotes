# 类加载与双亲委派

> [!question] 疑问
> 双亲委派是什么、有啥用？类加载过程分几个阶段？

## 一图看懂双亲委派

![[双亲委派模型.svg]]

一句话：**收到加载请求先委派给父加载器，父加载器一路向上，都搞不定才自己加载**。"双亲"不是继承关系（加载器之间是组合/成员变量），是层级委派关系。

| 加载器 | 职责 | 备注 |
| --- | --- | --- |
| Bootstrap | JDK 核心类（java.lang.* 等） | C++ 实现，Java 里拿不到它 |
| Platform | 平台模块的类 | **JDK 9 由 Extension 扩展类加载器更名**（extension 目录随模块化移除） |
| Application | classpath + 依赖 jar | 我们写的类默认走这里 |
| Custom | 自定义来源（网络/加密 class） | 重写 `findClass()`，别动 `loadClass()` |

**作用四点**：① 类的唯一性（同一类只加载一次，两份同名类 = `ClassCastException` 地狱）② 安全性（自定义 `java.lang.String` 永远顶不掉 JDK 的）③ 核心类只加载一次，全层级复用 ④ 层次清晰便于隔离。

> [!warning] 高频追问：谁打破了双亲委派？
> - **SPI / JDBC**：核心库要加载厂商驱动（classpath 里），Bootstrap 只能反过来"委托子加载器" → **线程上下文类加载器**
> - **Tomcat**：每个 webapp 一个独立加载器，且**优先自己加载**（实现应用间依赖隔离）
> - **OSGi / 热部署**：网状委派。能讲出 JDBC 和 Tomcat 两个例子就够了

## 类加载生命周期

![[类加载生命周期.svg]]

**加载 → 链接（验证/准备/解析）→ 初始化 → 使用 → 卸载**，各阶段最容易考的细节：

| 阶段 | 考点 |
| --- | --- |
| 加载 | 全限定名 → 字节流 → 方法区数据结构 + 堆里的 **Class 对象** |
| 验证 | 文件格式 / 元数据 / 字节码 / 符号引用，四道校验 |
| 准备 | 静态字段分配内存并设**默认值**（int=0）；**`static final` 编译期常量（ConstantValue）此时直接赋真值**；`static final Object o = new Object()` 这种运行期才定的仍在初始化阶段赋值 |
| 解析 | 常量池**符号引用 → 直接引用**（指针/偏移量/句柄） |
| 初始化 | 执行 `<clinit>()`（静态赋值 + static 块，编译器生成，**父类先执行**）；**JVM 保证 clinit 加锁执行** —— 静态字段循环依赖可造出类初始化死锁 |
| 卸载 | 三条件缺一不可：实例全回收 + **ClassLoader 被回收** + Class 对象无引用；核心类基本永不卸载 |

## 触发初始化：主动引用 vs 被动引用

- **主动引用（触发）**：new / 读写非常量静态字段 / 调静态方法 / 反射 / main 主类 / 子类初始化牵连父类
- **被动引用（不触发）**：`Sub[] arr = new Sub[10]`（只建数组类）、引用编译期常量（已进常量池）、通过子类引用父类静态字段（只初始化父类）

> [!tip] 一句话速记
> **加载看门牌（全限定名），链接验房产（验证/准备/解析），初始化搬进去住（clinit）；找类先问爹，爹不行自己上。**
