# static 关键字与内部类

> [!question] 疑问
> 解释 Java 中的静态变量和静态方法；静态内部类和非静态内部类有什么区别？

## 静态变量和静态方法

核心一句话：**static 成员属于类本身，不属于任何对象，全类只有一份，所有实例共享。**

### 静态变量（类变量）

用 `static` 关键字声明的变量，属于类而不是任何具体的对象。三个特点：

- **共享性**：所有实例看到的是同一个变量，一个实例改了，其他实例立刻可见
- **初始化时机**：类加载时初始化，只分配一次内存（在 JVM 的方法区/元空间，早于任何对象创建）
- **访问方式**：`类名.字段` 或 `实例.字段` 都合法，但推荐类名——通过实例访问容易让人误以为这个变量属于那个实例

### 静态方法

- 同样通过类名调用
- **不能直接访问实例变量和实例方法**（没有 `this` 引用）
- 不能被 override：重写是多态的产物，静态方法绑定的是类，子类同名静态方法只是"隐藏"而非重写

## 静态内部类 vs 非静态内部类

所有区别可以归成一个根源：**非静态内部类持有外部类实例的引用（隐式的 this），静态内部类不持有**。其他区别全是这句话的推论。

| 维度 | 非静态内部类 | 静态内部类 |
| --- | --- | --- |
| 依赖外部实例 | 是，必须先 `new Outer()` | 否，独立实例化 `new Outer.Inner()` |
| 能访问外部什么 | 实例成员 + 静态成员（包括私有的） | 只能访问外部的静态成员 |
| 能否定义 static 成员 | 不能 | 可以 |
| 私有成员访问 | 能直接访问外部私有成员 | 不能直接访问外部实例的私有成员 |

### 编译器是怎么做到的？（本题精华）

编译器在生成字节码时，给非静态内部类自动加一个 `this$0` 字段（类型就是外部类）；创建内部类实例时必须传入外部实例，构造器把这个引用存进 `this$0`。内部类里"直接访问"外部成员的代码，编译后实际是 `this$0.xxx`。

> [!tip] 记忆锚点
> **内部类能不能访问外部实例成员，取决于它手里有没有那个实例的引用。** 所谓"直接访问"只是编译器替你维护并使用了一个隐藏的外部类引用。

## 面试加分延伸点

1. **内存泄漏是最高频的追问**
   非静态内部类隐式持有外部类实例引用，如果内部类对象生命周期比外部类长（典型：Handler 匿名内部类持有 Activity 引用，而消息队列还压着它），外部类就无法被 GC——Android 的 Handler 内存泄漏就是经典案例。解决办法：改成静态内部类 + `WeakReference`。
2. **静态内部类为什么不能访问外部实例成员**
   没有 `this$0`，拿不到外部实例——一切回到"有没有引用"这个根源。
3. **静态内部类的实用场景**
   不依赖外部实例、逻辑上归属外部类的类。经典例子：`HashMap.Node`（链表节点不需要持有 Map 实例）、**静态内部类单例模式**（利用类加载机制保证线程安全的懒加载）。
4. **匿名内部类**也是非静态内部类，同样隐式持引用，是 `this$0` 泄漏问题最常见的形态。
