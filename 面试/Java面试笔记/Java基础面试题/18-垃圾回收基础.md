# 垃圾回收基础

> [!question] 疑问
> 什么是 Java 的垃圾回收？如何触发？怎么判断垃圾、怎么回收？收集器有哪些？

## 什么时候触发 GC

| 触发方式 | 说明 |
| --- | --- |
| 自动：内存不足 | Eden / 老年代分配不下新对象时自动触发，主力路径 |
| 自动：阈值策略 | 收集器内部按对象年龄、内存占用比例触发 |
| 建议：`System.gc()` | 只是建议，JVM 可忽略；生产上常配 `-XX:+DisableExplicitGC` 禁掉，防止有人乱调引发 Full GC |
| 参数：`-Xms / -Xmx` | 初始 / 最大堆大小，影响 GC 频率（配成一样可避免堆动态伸缩） |

## 判活：可达性分析

![[可达性分析判活.svg]]

| 算法 | 原理 | 短板 | 谁在用 |
| --- | --- | --- | --- |
| 引用计数法 | 引用 +1 / 失效 -1，归零回收 | **循环引用无法回收** | JVM 不用；Python、Netty 用（另配解法） |
| 可达性分析 | 从 GC Roots 沿引用链追溯，不可达即垃圾 | 需要停顿（STW）扫描 | **JVM 全家** |

GC Roots 五样（记忆：**栈、静态、常量、JNI、活线程**）——"正在被用的东西都是根"。

## 怎么收：分代模型 + 三大算法

![[分代回收与三大算法.svg]]

分代的依据是**对象寿命分化**：绝大多数对象朝生夕死（用复制最划算），少数长寿对象（用整理更划算）。

- 新生代默认 **Eden : S0 : S1 = 8 : 1 : 1**；晋升年龄默认 15（`-XX:MaxTenuringThreshold`）
- Minor GC 频繁但快；**Full GC 整堆、最慢，调优的第一目标就是让它少发生**
- 三大算法没有谁更好，只有配谁：复制配新生代（存活少），整理配老年代（存活多、怕碎片）

### 三大算法逐步图解

![[三大算法图解.svg]]

三句话记住取舍：

- **标记-清除**：最简单，但存活对象原地不动 → 碎片是硬伤，大对象放不下会提前触发回收
- **标记-复制**：空间换时间，存活越少越快、天然无碎片 → 新生代标配（Eden:S0:S1 = 8:1:1 就是为了少浪费）
- **标记-整理**：无碎片，但要移动对象、更新所有引用，停顿更长 → 老年代标配

> [!tip] 面试手画题
> 面试可能直接让你画这三个过程。图里格子数是守恒的：标记后 6 个存活对象，复制/整理后还是 6 个 —— 画错数量是最常见的失分点。

## Minor / Major / Full GC

| 类型 | 作用范围 | 触发条件 | 特点 |
| --- | --- | --- | --- |
| Minor GC（Young GC） | 新生代（Eden + S0/S1） | Eden 满 | 最频繁、最快，STW 短 |
| Major GC | 老年代为主 | 老年代空间不足 | 低频、慢（存活率高） |
| Full GC | 整堆 + 元空间 | 见下方清单 | **最贵**，STW 最长，调优头号敌人 |

> [!warning] 术语没有统一标准
> "Major GC" 在不同资料/收集器里含义不同：有的指老年代回收，有的直接等同 Full GC。面试建议先说一句"Major GC 术语有歧义"，再按 Minor / Major / Full 三分法讲，显得严谨。

**Full GC 触发清单**：

1. 老年代空间不足（晋升过快 / 大对象直接进老年代放不下）
2. Minor GC 后**担保失败**：存活对象老年代装不下（Promotion Failed）
3. 元空间（JDK 8+）/ 永久代不足
4. `System.gc()`（建议性，可被 `-XX:+DisableExplicitGC` 禁掉）
5. CMS 的 Concurrent Mode Failure → 退化 Serial Old（见 [[19-CMS与G1收集器]]）

## 追问必备：四种引用

| 引用 | 回收时机 | 典型场景 |
| --- | --- | --- |
| 强引用 | 只要可达就不回收 | 普通赋值 |
| 软引用 | 内存不足才回收 | 缓存 |
| 弱引用 | 下次 GC 必回收 | **ThreadLocal 的 key**（见 [[16-ThreadLocal原理与内存泄漏]]） |
| 虚引用 | 形同虚设，仅用于通知 | 堆外内存回收跟踪（DirectByteBuffer） |

## 收集器演进（一句话版）

**Serial（单线程）→ Parallel（吞吐优先）→ CMS（低停顿，碎片问题，JDK 14 已移除）→ G1（JDK 9+ 默认，分 Region、可预测停顿）→ ZGC（亚毫秒停顿，堆越大越香）**

> [!tip] 一句话速记
> **判活看可达，回收看分代：Minor GC 复制快，Full GC 整堆慢，调优让 Full 少发生。**
